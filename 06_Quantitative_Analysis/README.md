# Quantitative Analysis of the 110 Included Studies

Supporting material for Comment 2.5 of the CSUR-2026-0777 major revision.

> Reviewer request: *"Providing a deeper analysis that includes publication trends by category, venue distribution, application-domain distribution, LLM model distribution, types of MRs across studies, and comparison of evaluation metrics would provide stronger evidence-based insights."*

This package answers the six requested dimensions from the corpus itself. Every number is generated by `analysis_script.py` from the artefacts already published in this repository, and every paper-level judgement is shipped with the evidence snippet it was derived from, so any figure can be checked against the corresponding PDF.

## Inputs

| Input | Use |
|---|---|
| `04_Cross-Validation_and_Final_Inclusion/Final_Classification_110.xlsx` (sheet `Final Labels`, header on row 8) | Research direction, primary function, quality attribute, application domain, MT lifecycle activity |
| `04_Cross-Validation_and_Final_Inclusion/Statistics_110.md` | Publication type and venue counts |
| `04_Cross-Validation_and_Final_Inclusion/Final_Papers/*.pdf` | Full text, used for the model / MR / metric dimensions |

## Method

Dimensions 1–3 come straight from the coded metadata of the 110 included studies and need no inference.

Dimensions 4–6 are not part of the coding schema, so they are extracted from the full text of each PDF. The method is deliberately mechanical and auditable:

1. Text is extracted from every PDF and the reference list is removed (everything from the `References` heading onward), so that citations cannot be mistaken for usage.
2. Each dimension is expressed as a fixed family lexicon (model families, MR types, metric families). The lexicons are listed verbatim in `analysis_script.py`.
3. A family is attributed to a study only when the pattern occurs at least N times inside the body text — 3 for models, 2 for MR types and metrics. Single passing mentions are discarded.
4. For every attribution the script writes the row number, study ID, occurrence count and a surrounding text window into a `*_mentions_per_study.csv` file, which serves as the verification sheet.

All families are multi-label. A study that evaluates both GPT-4 and LLaMA counts once in each row, so column totals exceed 110 and shares are not additive.

## Headline numbers

- 110 studies, published 2020 and 2023–2026. 87 of them (79.1%) appeared in 2025 or 2026.
- The MT-for-LLMs direction accounts for 71 studies (64.5%), LLMs-for-MT for 27 (24.5%), and 12 studies (10.9%) contribute to both.
- Peer-reviewed venues dominate: 81 studies (73.6%), with ICSE (8), ASE (6), COMPSAC (5) and PACMSE (5) leading. Preprints account for 27 studies (24.5%).
- Only 37 of the MT-for-LLMs studies name a concrete application domain, most often Dialogue & Agentic Systems (21) and Code Generation & Repair (16).
- GPT-4 family models appear in 45 studies, the ChatGPT / GPT-3.5 family in 37 and the LLaMA family in 33; 24 studies use none of the tracked families.
- 54 studies report using LLMs to generate or discover metamorphic relations, against 17 that rely on human-specified or domain-knowledge relations.
- Accuracy (62 studies) and precision / recall / F1 (41) are the most common metrics, while 18 studies evaluate MR violation or failure rate and 27 report false-positive behaviour.

## Limitations

- Dimensions 4–6 are text-derived, not human-coded. They capture whether a family is used in a study, not which models are the primary evaluation target.
- Generic usages of the word `coverage`, `accuracy` or `ChatGPT` inside the body text are counted; the evidence sheet is the intended place for spot-checking, and any row can be revised without touching the pipeline.
- Studies that evaluate a model without naming it, or that name a model only in an appendix, are counted as "none of the families above". The 24 studies in that bucket include work on non-LLM baselines such as BERT-era models.
- Shares are per study and multi-label; they should be read as coverage of the corpus, not as a partition.

## Reproduction

```
cd 06_Quantitative_Analysis && python3 analysis_script.py
```

Requires `pymupdf` and `openpyxl`. The script reads only the four inputs listed above and writes its output next to itself. It takes the evidence repository to be the parent of this folder by default; set `EVID=/path/to/MTLLMSurvey-evidence` when the repository lives elsewhere.
